#### Lab 5, part 1.

In this lab, you'll install Ollama, learn to pull and run models locally, and look under the hood at a few very simple harnesses to start to get a sense for what makes LLMs work.

Hang on to your answers for this part and include them with the remainder of Lab 5.

1. To begin, please install Ollama from here: https://ollama.com/
You might be familiar with similar tools such as LMStudio - the difference is that ollama is a) intended to be a command-line tool and b) has an API that allows you to interact programmatically with LLMs. 

You'll also need to install the ollama Python package. You can do that with pip. 

2. Ollama allows you to run models *on your own computer*. The advantage here is that you don't need to pay for tokens or worry about your data being used by someone else. The disadvantage is that you probably can't run the largest and most recent models on your laptop. But we can do a lot with a smaller model.
To begin, pull the orca-mini model. This is a very small, older model that's easy to download.

Do this with: 
```
ollama pull orca-mini.
```

You can run it from the command line with:

```
ollama run orca-mini
```

Try some queries on this. How does it do?

3. Take a look at example1.py. This shows how to call a model programmatically. It uses the 'chat' function, taking a dictionary of messages, each containing a 'role', which can be an instruction to the model about how to reply, and a 'content', which is the actual question being asked. 
Take a look at the response. What else is contained in it?

4. Orca-mini is not very powerful. Let's try something a little bigger . Pull llama3.1 with 

```
ollama pull llama3.1. 
```
This is about 5GB. 

Try running that from the command line with 
```
ollama run llama3.1.
```
 
Give it the same queries you used for orca-mini. Does it do better? Are there still places where it gets confused?

5. Look at example2. This shows how to implement a simple multi-turn chat. As you can see, the response for each question gets added into the messages for the following iteration. 
Run this, ask a few questions, and look at what is being sent back to the model. Now that you see how it works, are there ways you can confuse or trick the model?

6. Ollama also lets us provide a system prompt, which gives the model instructions about how to respond. This is where we would provide guardrails or instructions about tone or context. Take a look at example3, which instructs llama3.1 to act as a tutor. How does that change the response? Are you able to get the model to ignore its system prompt?

7. By themselves, LLMs are unable to interact with the outside world. All they can do is receive an input string and generate an output string. In order to improve their ability to generate useful responses and reduce hallucinations, developers have introduced a number of different ways for models to use *tools*. 
	
	To begin, we'll need a model that has been trained to call tools. Please pull qwen3. This is a model from deepseek that is able to reason about tools. 
	Then take a look at example4. This file creates two demo tools, 'get_temperature' and 'get_conditions'. (These just produce fake data; a real tool would contain some sort of API call to a weather service.)
	Try running the file. You should see the reasoning traces that are generated by qwen as it tries to answer each question. 
	Now change it so that one of the cities is 'San Francisco'. What is the result? Can you see where in the reasoning chain that the model is trying to figure out what to do with San Francisco?
	
	Now remove the typing information (both the hints and comments) that describe what the tools do, and what they take as inputs. Is your model still able to solve the problem?
